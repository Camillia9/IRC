2.4 Buffer circulaire et extraction de lignes (1-1.5 jours) 🔴 PARTIE CRITIQUE

Problème à résoudre :

    Un recv() peut recevoir plusieurs messages : "JOIN #test\r\nPART #test\r\n"

    Un recv() peut recevoir un message incomplet : "PRIVMSG #chan :Hel" puis "lo\r\n"

    La limite IRC est 512 caractères incluant \r\n

Ce que tu dois faire :

    Chaque Client a un attribut std::string buffer (buffer de réception personnel)

    Quand recv(fd, temp, 1024, 0) reçoit des données :

        Ajouter les données reçues au buffer du client : client.buffer += temp

        Chercher \r\n dans le buffer

        Si trouvé : extraire la ligne complète, la retirer du buffer

        Appeler la fonction de Laurent pour traiter cette ligne complète

        Continuer à chercher d'autres \r\n dans le buffer (car peut y avoir plusieurs messages)

    Vérifier que le buffer ne dépasse jamais 512 caractères (sinon erreur + déconnexion)

Interface avec Laurent :
Tu dois fournir une fonction callback ou appeler directement :

text
processCommand(Client* client, std::string line_complete)

Cette fonction sera codée par Laurent dans son dispatcher.

Pourquoi c'est critique :
Sans cette gestion, les messages seront coupés ou mélangés, le serveur ne comprendra rien.

🟢 LAURENT : Parsing messages + Logique métier

🟡 PRIORITÉ ABSOLUE - Dépend vaguement de Phase 1 de Chloé (structure Client)

Contenu détaillé :
1.1 Comprendre le format IRC (0.5 jour) 📚

Étudier le format des messages IRC selon la RFC :

text
[:<prefix>] <COMMANDE> [<param1> <param2> ... <paramN>] [:<dernier paramètre avec espaces>]

Exemples à parser :

    NICK Alice → commande=NICK, params=[Alice]

    JOIN #general → commande=JOIN, params=[#general]

    PRIVMSG #test :Hello world → commande=PRIVMSG, params=[#test, "Hello world"]

    :Alice!user@host PRIVMSG Bob :Salut → prefix=Alice!user@host, commande=PRIVMSG, params=[Bob, "Salut"]

    MODE #chan +o Bob → commande=MODE, params=[#chan, +o, Bob]

Règles importantes :

    Le prefix (commence par :) est optionnel (les clients n'en envoient généralement pas)

    Les espaces séparent les paramètres

    Le dernier paramètre peut commencer par : pour inclure des espaces

    La commande est toujours en MAJUSCULES (ou doit être convertie)

1.2 Créer la structure ParsedMessage (0.5 jour)

Définir une structure pour stocker le résultat du parsing :

    std::string prefix (vide si pas de prefix)

    std::string command (ex: "JOIN", "PRIVMSG", "MODE")

    std::vector<std::string> params (liste des paramètres)

1.3 Fonction de parsing (2 jours) 🔴 PARTIE DIFFICILE

Créer une fonction qui prend une ligne complète (sans \r\n) et retourne un ParsedMessage.

Étapes du parsing :

    Extraire le prefix (si présent) :

        Si la ligne commence par :, chercher le prochain espace

        Tout entre : et l'espace est le prefix

        Retirer le prefix de la ligne

    Extraire la commande :

        Chercher le prochain espace

        Le mot avant l'espace est la commande (convertir en majuscules)

    Extraire les paramètres :

        Tant qu'il reste des caractères dans la ligne :

            Si le mot commence par :, tout le reste de la ligne est le dernier paramètre

            Sinon, extraire le mot jusqu'au prochain espace

            Ajouter à la liste des paramètres

Gestion des erreurs :

    Ligne vide → ignorer

    Commande vide → erreur

    Trop de paramètres (>15) → erreur selon IRC

Tests unitaires à faire :
Tester avec plein d'exemples pour vérifier que ça marche correctement.

Phase 6 : Commande MODE ⏱️ 4-6 jours

🔴 PARTIE LA PLUS COMPLEXE - À faire en dernier

Contenu détaillé :
6.1 Comprendre MODE (0.5 jour) 📚

Deux utilisations :

    Query : MODE #channel → demander les modes actifs

    Set : MODE #channel +o Alice → modifier les modes

Syntaxe complexe :

    Modes peuvent être combinés : MODE #chan +oi-k Alice secret

    Certains modes prennent des paramètres, d'autres non

    + active, - désactive

Modes à implémenter :

    +i/-i : invite-only (pas de paramètre)

    +t/-t : topic protégé (pas de paramètre)

    +k : mot de passe (paramètre = password), -k : retirer mot de passe (pas de paramètre)

    +o : donner opérateur (paramètre = nickname), -o : retirer opérateur (paramètre = nickname)

    +l : limite utilisateurs (paramètre = nombre), -l : retirer limite (pas de paramètre)

6.2 Parser MODE (1-1.5 jours)

C'est un sous-parser dans ton parser 🤯

Étapes :

    param = nom du channel

    param = string de modes (ex: "+oi-k")

    ​

    params[2..N] = paramètres associés aux modes (dans l'ordre)

Exemple : MODE #chan +oki-l Alice secret

    Modes : +o +k +i -l

    Paramètres : Alice (pour +o), secret (pour +k)

    +i et -l n'ont pas de paramètre

Parser à créer :

    Parcourir le string de modes caractère par caractère

    Détecter + ou - pour savoir si on active ou désactive

    Pour chaque mode, vérifier s'il nécessite un paramètre

    Associer les paramètres aux bons modes

6.3 Vérifications et permissions (0.5 jour)

    Vérifier que le channel existe → erreur 403

    Vérifier que le client est membre → erreur 442

    Pour changer les modes : vérifier que le client est opérateur → sinon erreur 482

    Vérifier que chaque mode est valide (i, t, k, o, l) → sinon erreur 472

6.4 Implémenter chaque mode (2-3 jours) 🔴

Mode +i/-i (0.5 jour)

    Activer : channel->modes['i'] = true

    Désactiver : channel->modes['i'] = false

    Effet : les futurs JOIN vérifieront ce flag

Mode +t/-t (0.5 jour)

    Activer : channel->modes['t'] = true

    Désactiver : channel->modes['t'] = false

    Effet : TOPIC vérifiera ce flag avant de changer le topic

Mode +k/-k (0.5 jour)

    +k secret : channel->password = "secret" et channel->modes['k'] = true

    -k : channel->password = "" et channel->modes['k'] = false

    Effet : JOIN vérifiera le password si ce mode est actif

Mode +l/-l (0.5 jour)

    +l 50 : channel->user_limit = 50 et channel->modes['l'] = true

    -l : channel->user_limit = 0 et channel->modes['l'] = false

    Effet : JOIN vérifiera le nombre de membres si ce mode est actif

Mode +o/-o (1 jour) ⚠️ Le plus délicat

    +o Alice : ajouter Alice à channel->operators

    -o Alice : retirer Alice de channel->operators

    Vérifications :

        Alice doit exister → erreur 401

        Alice doit être membre du channel → erreur 441

    Notifier tous les membres :

        Format : :operator!user@host MODE #channel +o Alice
